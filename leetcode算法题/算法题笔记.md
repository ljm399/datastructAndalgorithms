# 解释2 * *31-1 和- 2 * *32 

```ts
二进制    十进制
000       0
001       1
010       2
011       3
100       4
101       5
110       6
111       7
```

### 为什么要减1

因为从0开始，则最高位（第n位）退回到n-1，即就是-1

- 例子3位的正数范围

```js
第1个  第2个  第3个  第4个  第5个  第6个  第7个  第8个
  0      1      2      3      4      5      6      7
```

而不是2**3 =8



### 为什么是31而不是31

32 位表示总共有 32 个二进制位：

```
最高位                 剩余 31 位
  ↓                        ↓
符号相关位  |  数值相关的二进制位
```

有符号整数需要同时表示正数和负数，所以范围是：

```
-2^(32 - 1) 到 2^(32 - 1) - 1
```



# 使用const num3 = String(Number(num1) + Number(num2)) 会有问题

测试数据很长时，JavaScript `Number` 会转成科学计数法，例如：

```
String(1000000000000000000000) // "1e+21"
```

随后你的循环把 `"1e+21"` 每个字符都建成节点：

```
Number('1') // 1
Number('2') // 2
Number('+') // NaN
Number('e') // NaN
```



### 解决

```ts
const num3 = (BigInt(num1 || '0') + BigInt(num2 || '0')).toString();
```

先把 `Number` 换成 `BigInt`，避免超大整数精度丢失和科学计数法

因为 `Number` 很大时可能变成 `"1e+21"`，你的后续循环会把 `e`、`+` 也当作数字节点，产生 `NaN`。

# longest palidromic substring算法题没做出来原因

**你不是少考虑了条件**，而是前面的思路从**“枚举候选子串**，再判断它是否回文”出发，所以需要不断**删左、删右、重新找中点**，状态自然会变复杂。

中心扩展法换了一个观察角度：**不去问“这个子串是不是回文”，而是问“以这里为中心，最远能扩展成多长回文”。**

关键是：**每一个回文子串都一定有中心。**

# 思维

### 先抽象再具体。

比如你今天学的。那个算法，你看别人答案的时候，你先。啊，把它那个想法给抽象出来。什么叫抽象呢？就是你脑子你想的那个东西。能够大致通过脑子过一遍他那个什么什么。过程在脑子已经形成了，然后你再把这个过程通过代码实现这个实践过程就要具体

抽象过程，你要必须先写下来，不要光靠小。同时也可以说写加说 因为写了说或者说的时候。他才让你更加理清理缺了什么怎么更快达达成目的吗？

### 代码复杂，往往不是语法复杂，而是抽象过程不够清晰。先把过程说清楚、写清楚，再写代码，代码通常会自然变简单
